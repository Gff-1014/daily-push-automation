# 六级单词推送系统 · 项目大纲（v5 上线参考版）

> 用途：本系统已完整开发并上线（2026-08-27 起每日 08:00 / 18:00 自动推送）。
> 本大纲同时作为**新项目的参考蓝图**：完整记录需求确认、系统设计、目录结构、
> 部署方式、费用测算与测试/回测工具，可直接借鉴其工程模式。

## 一、项目定位与需求确认

备考 2026 年 12 月英语六级。按考研 / 六级 / 四级 / 小学 / 初中词表并集推送单词，
100 天周期，每天 08:00 与 18:00 各推送一次（周末照常）；每次包含新学单词、回忆单词、
一篇当日英文新闻改写阅读、文中生词表及中文翻译。

| 需求项 | 确认内容 |
| --- | --- |
| 目标考试 | 2026 年 12 月英语六级（CET-6），`end_date` 留空按 100 天，设置后自动倒排 |
| 学习周期 | 100 天，每天均推新词（含周末）；`started_on` 可播种指定开始日 |
| 词表范围 | 考研 ∪ 六级 ∪ 四级 ∪ 小学 ∪ 初中，查重后四分类，全量 6900 词 |
| 词条字段 | 单词、词性、音标（统一 `/.../`）、汉意、分类标签、词频 |
| 分类与优先级 | 6研共有 > 6级独有 > 考研独有 > 小初共有 |
| 组内排序 | 按词频从高到低出队 |
| 推送时间 | 08:00（早间）+ 18:00（晚间），周末照常；开始日之前自动跳过 |
| 每次推送内容 | 新学单词 + 回忆单词 + 阅读材料 + 文中生词表 + 阅读翻译 |
| 阅读材料 | 当日英文新闻改写为六级难度短文（约 200–300 词），不配题目 |
| 回忆单词 | 直接显示释义（单词 + 音标 + 词性 + 汉意，弱回忆模式） |
| 推送渠道 | 复用现有 SMTP 配置（只读 `.env`），QQ 邮箱发件 |
| 部署 | 腾讯云 SCF 独立函数 `vocab_push` + 两个定时触发器，不影响新闻项目 |

### 2.1 数据来源

| 用途 | 来源 | 说明 |
| --- | --- | --- |
| 考研词表 | maimemo-export「2018 考研英语大纲词汇 5500」 | 去重后 5598 词 |
| 六级词表 | maimemo-export「六级新大纲词汇表」 | 去重后 5323 词 |
| 四级词表 | KyleBing english-vocabulary 四级 | 去重后 4543 词 |
| 小学 / 初中词表 | maimemo-export + KyleBing | 532 / 1987 词 |
| 释义 | KyleBing 考研 / 六级 / 四级词库 | 单词 + 词性 + 多条释义 |
| 音标 | ipa-dict + eng_to_ipa + 手工补表 | 覆盖率 100% |
| 词频 | FrequencyWords en_50k | 覆盖率 96.7%，组内降序 |

处理流程：统一小写 → 列表内去重 → 跨表查重 → 补释义 / 音标 / 词频 →
清理格式（合并空格、去多余标点）→ 产出统一 JSON。

### 2.2 四分类统计（实测）

| 分类 | 判定规则 | 词数 |
| --- | --- | --- |
| 6研共有 | （考研 ∩ 六级）∪ 四级词表 | 4010 |
| 6级独有 | 六级 − 考研 | 663 |
| 考研独有 | 考研独有非四级 + 口语俚语词（27 个） | 343 |
| 小初共有 | 小学 ∪ 初中（基础词优先） | 1884 |
| **合计** | 考研 ∪ 六级 ∪ 四级 | **6900** |

判定顺序：口语/俚语词 → 考研独有；小学/初中词 → 小初共有；四级与考研∩六级 → 6研共有；
六级独有 → 6级独有；其余 → 考研独有。

## 三、100 天学习计划（已完成）

### 3.1 每日配额（自动均摊，不写死）

| 分类 | 词数 | 每日新词 |
| --- | --- | --- |
| 6研共有 | 4010 | 40~41 个/天（早晚各约 20） |
| 6级独有 | 663 | 6~7 个/天 |
| 考研独有 | 343 | 3~4 个/天 |
| 小初共有 | 1884 | 18~19 个/天 |
| **每日合计** | **6900** | **约 69 个（早晚各约 34~35）** |

- 调度器按 `ceil(剩余词数 / 剩余天数)` 自动均摊，最后一天精确收官 6900/6900；
- 确定考试日期后设置 `end_date`：自动倒排并预留考前 14 天冲刺复习期（只复习不推新词）；
- 状态字段 `started_on` 决定 Day 1；播种脚本可在正式推送前指定开始日（开始日前触发自动跳过）。

### 3.2 SRS 间隔复习

```
学习当天（晚间回测）→ 次日 → 第 2 天 → 第 4 天 → 第 7 天 → 第 15 天 → 第 30 天
```

- 每次推送复习词上限 25 个，超出顺延；
- 回忆单词直接显示释义；
- 状态记录在 `data/vocab/state.json`：新词游标、SRS 队列、day_plan、邮件失败计数、暂停标记；
- 云端状态存 COS（`vocab/state.json`），本地 JSON + COS 双向同步，失败不丢进度。

## 四、每日推送内容与格式（最终版）

### 4.1 推送结构（HTML 邮件，纯文本版同步支持）

```
【六级单词打卡】2026-08-27 早间（Day1，37/6900）

一、今日新词（37 个）
  【6研共有】（21 个）   → 1. oh /oʊ/  int. 嗬，哦，唉呀
  【6级独有】（4 个）    → 单词 音标 / 词性 释意（多词性每行一个）
  【考研独有】（2 个）
  【小初共有】（10 个）  → 小初排在最后

二、回忆单词（N 个）      → 直接显示 单词 音标 / 词性 释意

三、今日阅读（约 N 词）
  【英文短文；生词/重难词用细下划线 + 上标数字标注，如 lower¹】

四、文中生词与重难词汇（N 个）
  【全局编号 1..N，与正文上标一一对应；按分类分块；单词 音标 / 词性 释意】

五、阅读翻译
  【全文中文翻译】

—— 晚上 18:00 见，晚间推送包含当日回测 + 第二篇阅读。
```

### 4.2 格式要点（用户逐项确认过的最终版）

| 项 | 最终样式 |
| --- | --- |
| 标题 | `Day{N}，已学/总词数`（如 Day1，37/6900），不使用"第一天" |
| 单词块 | 第一行 `单词 音标`；第二行起 `词性 + 对应释意`，多词性各占一行 |
| 分类段 | 4 类按 6研共有 → 6级独有 → 考研独有 → 小初共有 排列 |
| 正文字号 | 文章区 22px（标题同 22px），正文其余 20px；无额外词间距 |
| 生词标注 | 正文生词：`<u>` 细下划线（1px）+ 红色上标数字；编号 = 生词表全局序号 |
| 生词表 | 全局连续编号，按分类分块展示，含音标/词性/释意 |
| 阅读来源 | 文末注明 RSS 来源 |

### 4.3 阅读生成流程（含容错）

1. 早间源：NPR Science / ScienceDaily / NPR Tech；晚间源：CGTN World/China / China Daily World/China；
2. 按日期轮换起始源，单源失败自动切下一源；
3. 抓取正文（截断 3000 字符）→ **单次 LLM 调用**完成改写 + 翻译（省一半调用费）；
4. LLM 失败自动重试（3 次，1.5s/3s 退避）；仍失败则用 RSS 摘要当正文 + 占位翻译兜底；
5. 完全无网络 / 无 Key 时用内置示例文章，保证流程可跑通。

## 五、技术架构与目录（新项目参考重点）

### 5.1 总体架构

```
腾讯云 SCF 定时触发器（08:00 / 18:00）
        │
        ▼
vocab_push 云函数（Python 3.9 / 512MB / 900s）
  ├─ RSS 抓取（requests + bs4）            ── 当日新闻
  ├─ DeepSeek V4 Flash LLM（src/llm.py）  ── 改写 + 翻译（单次调用）
  ├─ 调度引擎（新词出队 + SRS 复习）        ── 每日计划
  ├─ 邮件渲染（HTML）                      ── 正文生成
  ├─ SMTP 直发（QQ 邮箱，复用 .env 配置）
  └─ COS 状态同步（学习进度，跨实例不丢）
```

### 5.2 目录结构（在新闻仓库内独立新增）

```
新闻总结/
├─ src/vocab/
│  ├─ words.py        # 词库加载、分组、按词频出队
│  ├─ srs.py          # SRS 间隔复习
│  ├─ state.py        # 学习进度状态（本地 JSON + COS）
│  ├─ plan.py         # 每日配额计算 + 提交计划
│  ├─ reading.py      # 新闻抓取 / LLM 改写翻译（含重试与兜底）
│  ├─ render.py       # 邮件正文渲染（HTML + 纯文本）
│  ├─ notifier.py     # SMTP/webhook 发送 + 失败告警
│  └─ main.py         # CLI + SCF handler 入口
├─ config/vocab.yaml  # 周期、SRS、阅读源、邮件配置
├─ data/vocab/        # words.json / state.json / 输出存档
├─ scripts/
│  ├─ build_vocab.py           # 词库构建
│  ├─ seed_vocab_start.py      # 播种开始日（可指定 Day1）
│  ├─ replay_morning_email.py  # 回测任意日期早间邮件（不写状态）
│  └─ preview_annotated.py     # 本地预览新版渲染
├─ tests/test_vocab.py         # 18 个单元测试
└─ deploy/deploy_vocab.py      # 独立部署脚本（vocab_push）
```

### 5.3 关键设计决策（可复用经验）

| 决策 | 做法 | 收益 |
| --- | --- | --- |
| 独立函数 | 新函数 `vocab_push` + 独立打包目录 | 不影响已有 `news_summary` / `send_mail` |
| 配置隔离 | `config/vocab.yaml` 独立，部署时只改打包副本 | 本地与云端配置互不污染 |
| 状态放 COS | 学习进度存 `vocab/state.json`，本地 + COS 双写 | SCF 多实例 / 冷启动不丢进度 |
| 单次 LLM 调用 | 改写 + 翻译一次完成（JSON 输出） | 每天 2 次调用，月费 <1 元 |
| LLM 重试 | 3 次尝试 + 退避，仍失败走兜底 | 消除 API 偶发失败 |
| 回测工具 | replay 脚本克隆云端状态到临时文件再渲染发送 | 新版本上线前可安全回放历史推送 |
| 开始日播种 | 状态预置 `started_on` + 代码跳过早于开始日的触发 | 精确控制 Day1，避免误推第 0 天 |

## 六、部署与运维（已完成）

### 6.1 部署

```bash
python deploy/deploy_vocab.py        # 构建包 + 上传 + 部署函数与触发器
python deploy/deploy_vocab.py --check  # 仅校验腾讯云密钥
```

- 函数：`vocab_push`（Python 3.9 / 512MB / 900s 超时 / handler `main.main_handler`）；
- 触发器：`v0800`（0 0 8 * * * *）、`v1800`（0 0 18 * * * *），已启用；
- 环境变量：DEEPSEEK_API_KEY、SMTP 系列、COS 桶、时区 Asia/Shanghai；
- 邮件：SMTP 直发（SMTP_SSL，失败自动尝试 STARTTLS 587），连续失败 3 次 → 告警邮件 + 暂停，恢复后补发。

### 6.2 费用测算（实测口径）

| 项目 | 用量 | 月费 |
| --- | --- | --- |
| DeepSeek V4 Flash（空闲时段 1.5/4.5 元每百万 tokens） | 每天 2 次 × ~2K 输入 + ~1.5K 输出 | ~0.6 元 |
| 腾讯云 SCF | 每月约 60 GB·秒 | 免费额度内，0 元 |
| 腾讯云 COS | 状态文件 KB 级 | 免费额度内，0 元 |
| **合计** | — | **约 0.5～1 元/月**（高峰时段运行最多 2 元） |

### 6.3 本地常用命令

```bash
python -m src.vocab.main morning --date 2026-08-29            # dry-run 预览（不发）
python -m src.vocab.main morning --date 2026-08-29 --send     # 发送并提交状态
python -m src.vocab.main --preview 100                        # 100 天配额预览
python scripts/replay_morning_email.py 2026-08-28             # 回测早间邮件（不写状态）
python -m unittest tests.test_vocab                           # 18 个测试
```

## 九、给新项目的参考清单

1. **先整理需求确认表再开发**：所有关键决策（格式、时间、来源、费用）逐条记录，避免返工；
2. **复用但不改动**：新功能用独立配置 / 独立函数 / 独立状态 key，与旧项目解耦；
3. **状态要可迁移**：云端函数必须把进度放 COS / 数据库，不能依赖本地磁盘；
4. **LLM 调用要可控**：单次调用完成多任务、低温参数、失败重试、无 Key 时 mock 兜底；
5. **交付前先回测**：用"克隆状态 → 临时渲染 → 发送"的方式验证历史邮件，不污染线上进度；
6. **费用先测算**：按 token 用量 × 单价 + 云资源免费额度，上线前给用户明确预估；
7. **标题计数可验证**：Day / 已学 / 总词数由状态游标推导，并用 3 天数据实测确认。
