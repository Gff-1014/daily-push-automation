# 每日央视网新闻文字总结系统 · 大纲框架（v3 已确认版）

> 目标：每日 08:30 与 20:30 两次运行，从央视网官网增量采集新闻，自动总结为简洁易读的纯文字，按「三大板块」归类输出；09:00 与 21:00 各推送一封汇总邮件，不逐条推送。

## 二、每日运行时间线

```
前一天 20:30 ──────────── 当天 08:30 ── 09:00 ──────── 20:30 ── 21:00
       ↑ 早间运行(08:30)：采集 20:30 → 08:30 发布新闻，09:00 推送
                              ↑ 晚间运行(20:30)：采集 08:30 → 20:30 发布新闻，21:00 推送
```

- 两段窗口（前一天 20:30 → 当天 08:30 / 当天 08:30 → 20:30）无缝衔接，合计覆盖完整 24 小时。
- 流水线在推送前半小时启动，处理完成后待机，由 09:00 / 21:00 的邮件触发器发送。
- 该时间表避开 DeepSeek 高峰时段（北京时间 9:00–12:00、14:00–18:00），两次运行均落在空闲/错峰时段，节省 API 费用。

## 三、分类体系与三大板块

### 板块一：主类新闻（六大类，每类单独总结）

| 主类 | 涵盖内容 |
| --- | --- |
| 政治 | 时政要闻、政策发布、外交动态、政务活动 |
| 经济 | 宏观经济、财经金融、产业发展、消费市场 |
| 科技 | 科技前沿、航空航天、互联网与 AI、创新成果 |
| 生活 | 民生政策、健康医疗、交通出行、住房消费、生活服务 |
| 国际 | 国际局势、海外热点、对外合作 |
| 社会 | 公共事件、社会治安、典型人物与正能量故事 |

每类新闻**单独成节**：先给该板块一句概述，再逐条列出新闻标题与简要总结。

### 板块二：次类新闻（合并统一整理）

涵盖：**文化教育、军事国防、生态环境**

不区分细分板块，所有内容直接统一整理为一个板块，逐条列出，不做子分类。

### 板块三：杂类新闻（合并统一整理）

无法归入主类或次类的新闻，统一归入「其他/杂类」，逐条列出。

### 归类规则

1. 每条新闻优先尝试归入六大主类。
2. 无法归入主类的，尝试归入次类（文化教育/军事国防/生态环境）。
3. 仍无法归类的，进入杂类。
4. 跨板块新闻取最相关的主类，不重复出现。
5. 若某板块当日无新闻，保留板块标题并标注「今日无相关新闻」或省略该板块（按展示偏好调整）。

## 四、新闻重要性排序（已确认：方案6 混合加权）

### 综合评分公式

```
S = 100 × (0.60 × S_LLM + 0.25 × S_热度 + 0.15 × S_关键词)
满分 100 分
```

三个信号统一归一化到 0–1 后加权合成并放大到百分制；板块内按 S 降序排列；同分时按发布时间从新到旧。

### 1. S_LLM（LLM 语义评分，权重 60%）

- LLM 按固定评分标准给每条新闻打 0–10 分：影响面、涉及人群数量、经济/民生影响程度、突发事件级别、政策含金量。
- 归一化：`S_LLM = LLM分数 / 10`。
- 为控制成本，评分可与总结生成合并为同一次 LLM 调用。
- 评分稳定性（不依赖人工抽查）：评分维度固定并带 0/5/10 分锚点描述、temperature 设为 0–0.3、输出结构化 JSON（分数+分维度分+理由）。

### 2. S_热度（传播热度加权，权重 25%）

- 数据来源（已确认）：**微博热搜、百度热搜、抖音热榜、B站热门**，四源默认等权，可配置。
- 获取方式（已确认）：**运行时热度**——每次运行开始时实时抓取四平台最新热榜，不依赖历史指数；聚合接口可用时优先，否则逐平台抓取兜底。
- 匹配逻辑：对每条新闻提取标题关键词（3–5 个，可由 LLM 生成），与四平台热榜词条做包含/核心词匹配；命中平台数越多、平台内排名越靠前，热度分越高。
- 归一化：按当日采集批次内 min-max 或排名分映射到 0–1。
- 无数据兜底：热度信号缺失时，权重按比例重分配给 LLM 与关键词（LLM 80% + 关键词 20%），并在日志中记录。

### 3. S_关键词（关键词规则加权，权重 15%）

- 维护分级重要词表并赋权（重大 / 重要 / 一般三档），来源：THUOCL 等领域词库 + 突发事件四分类（自然灾害/事故灾难/公共卫生/社会安全）+ 权威机构词（国务院、部委、中央等）+ 政策热词。
- 公式：`S_关键词 = min(Σ wᵢ × 命中次数, 上限) / 上限`，归一化到 0–1。
- 词表存放于 `config/` 配置文件，按板块维护，后续可用 LLM 定期辅助扩展。
- 新词标记规则：命中「新词标记词」（首发/问世/研制成功/获批/成功发射等）时，本条新闻关键词分按重大档累加，同板块领域词提升一档。
- 初始权重：重大 10 / 重要 5 / 一般 2，关键词分上限 30，均可配置。

### 排序规则

- 三大板块各自内部排序；主类中六个子类分别排序。
- 排序在总结生成之后、最终输出之前执行。
- 权重（60/25/15）为全局默认值，后续可按板块调参。

### 推送门槛与板块上限

- **基准门槛（严格执行）**：满分 100 分，**低于 55 分的新闻一律不推送**；即使板块未满、排名靠前，也不进入正文。
- **来源加权**：央视网·朝闻天下、央视网·新闻联播 来源条目最终评分 +8 分（满分 100 封顶，可配置）。
- **早间额外门槛**：早间推送中，财经 / 科技 / 政治 / 国际 ≥55 分即可推送；生活 / 社会 / 次类 / 杂类低于 **65 分**不推送。
- **晚间门槛**：全部类别按 55 分基准执行。
- **板块上限**：六大主类（政治/经济/科技/生活/国际/社会）每类最多推送 **10 条**；次类（文化教育/军事国防/生态环境合并）共最多 **15 条**；杂类最多 **10 条**。均按评分降序截取。
- 执行顺序：先按 60 分过滤 → 按 S 降序排序 → 按各板块上限截取 → 输出。
- 「附：原始新闻链接」默认只列已推送新闻，与正文一致。

## 五、采集与增量逻辑

### 采集入口（已确认：方案 A）

- 首页要闻 + 央视新闻「24小时」滚动列表 + 主类/次类对应频道列表页（时政、财经、科技、国际、社会、文化教育、军事、生态），共约 10 个入口。
- 频道页与三大板块对应：时政→政治、财经→经济、科技→科技、国际→国际、社会→社会，文化教育/军事/生态→次类。
- 新增 **财联社（cls.cn）** 作为财经 / 科技 / 政治类的补充来源，采集范围为**重要标记快讯 + 资讯文章**（已确认），与央视网内容合并去重。
- 早间时段（08:30 运行）额外启用**国外新闻来源**（已确认）：央视网国际频道 + 新华网国际 + 环球网 / 参考消息（中文源），仅早间启用，晚间仍按原来源。

### 采集窗口

| 运行 | 采集时间窗口 |
| --- | --- |
| 每日 08:30 | 前一天 20:30 之后 → 当天 08:30 之前发布的新闻 |
| 每日 20:30 | 当天 08:30 之后 → 当天 20:30 之前发布的新闻 |

### 增量规则

- 以央视网页面标注的发布时间为准（时区：Asia/Shanghai）。
- 系统记录「上次成功推送时间」，每次运行从上一次成功推送时间起采集，避免遗漏。
- 若某次运行失败，下次运行时自动补采（覆盖失败窗口），并记录告警日志。

### 去重与合并（已确认）

- 同次运行内：多平台/不同标题但内容大体相同的新闻，通过「标题归一化哈希 + LLM 语义相似判断」合并为一条，避免多份相同推送。
- 标题归一化：去除标点空格、媒体名前缀，数字归一化。
- **复查机制**：哈希命中视为确认重合，直接合并；语义相似处于模糊区间的「疑似重合」先进入复查（LLM 对比标题+摘要严格判定），确认后才合并；复查未确认的保留为两条并记入日志。
- 跨时段：与「已推送指纹」（保留 10 天）比对，内容相同的新闻不再重复推送；重大事件持续报道只保留首次推送。
- 状态文件（COS 极小对象，非内容归档）：记录上次成功处理时间 + 已推送指纹（**保留 10 天**，过期自动清除）+ 失败告警标记；下次运行前清理归档数据，但保留状态文件。

## 七、邮件推送方案（已上线：SMTP 直发）

### 推送形态（已确认）

- 每次运行结束后，将当日全部总结（三大板块 + 附链接）合并为**一封邮件**发送。
- **不逐条推送**任何新闻。
- 邮件主题：`8月26日新闻与热点（晚间）`（早间运行对应 `8月26日新闻与热点（早间）`）。
- 邮件正文：完整纯文字总结（即第六节模板全文）。

### 对接方式

- **实现方式**：`news_summary` 云函数内置 smtplib 直发（163 邮箱 SMTP 465 端口，TLS 1.2+），收件为 QQ 邮箱；不再依赖已下线的 API 网关触发器。
- 发送时机：每日 09:00 / 21:00 由独立邮件触发器调用，读取 COS 中暂存的总结发送，成功后清理。
- 配置：`SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_AUTH_CODE` / `MAIL_TO` 全部走环境变量（`.env` 或云函数环境变量），代码中不含明文凭据。
- 可选兼容：若配置 `EMAIL_WEBHOOK_URL`，则优先走 Webhook（函数 URL / 自建邮件服务）。
- 失败处理（已确认）：本次运行内即时重试（默认 3 次）；仍失败则跨运行累计失败次数 +1；**累计达到 3 次后**发送警告邮件，并置「暂停」标记，此后定时运行直接跳过（不再重复告警）；用户手动修复后恢复运行。
- 恢复机制：向云函数发送事件 `{"action":"resume"}`，清除暂停标记与失败计数，并补发未送达总结。
- 早间 / 晚间两封邮件相互独立；某时段无新闻时跳过发送并记录日志。

## 十、里程碑规划

## 十一、运维手册

- **部署/更新**：`python deploy/deploy.py`（自动构建 → 上传代码 → 更新函数与触发器）
- **检查云端状态**：`python scripts/check_state.py`（可选，读取 COS 状态）
- **恢复运行**：向函数发送事件 `{"action":"resume"}`
- **定时触发器**：`t0830` / `t2030`（运行）、`t0900` / `t2100`（发信），事件参数按 TriggerName 自动路由
- **日志**：腾讯云 SCF 控制台「日志查询」
- **凭据管理**：全部通过 `.env`（已 gitignore）或云函数环境变量注入，仓库不含明文密钥
